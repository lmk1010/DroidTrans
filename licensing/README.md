# 授权系统

卓传的收款与授权。收款走 Waffo Pancake，授权用 Ed25519 签名的许可证。

```
用户在官网点购买
  └─ POST /api/checkout   → Waffo 结账页
       └─ 付款成功
            └─ Waffo webhook → POST /api/webhook → 生成激活码，邮件发给用户
                 └─ 用户在客户端输入激活码
                      └─ POST /api/activate → 签发许可证 → 落到本机
                           └─ 之后完全离线验证
```

## 为什么必须能离线

卓传是局域网工具。用户插着数据线往电脑倒照片时，那台机器很可能压根没连外网。
**做成每次联网校验，等于把已经付过钱的人关在门外** —— 这是这类软件最常见、
也最伤用户的事故。

所以：只有「拿激活码换许可证」那一步需要网络，之后全程离线。

## 防破解：三层，以及它们的边界

先说清楚前提：**任何客户端验证都能被 patch 掉，联网的也一样**（改 hosts 即可）。
所以目标不是「防住所有人」，而是让白嫖的代价高于 $1.99。
过度防护的成本会先落到正常用户头上。

### 第一层 · 签名（防伪造）

许可证是 `base64url(JSON) + "." + base64url(Ed25519 签名)`。
私钥只在这台服务器上，**任何人都无法自己生成一份有效许可证**。

拦得住：自己造码、改档位（把年付改成终生）、改邮箱。
拦不住：把整份许可证复制给别人。

### 第二层 · 设备名额（防批量分享）

一个激活码最多在 5 台设备上激活（`MAX_ACTIVATIONS`）。
买断制锁死一台会激怒正当用户（换电脑、重装系统），无限则等于放弃收费。

客户端会生成一个不含硬件信息的稳定随机 `device_id`。同一设备重复激活、
恢复购买或重装 App 不会重复占名额；用户在旧设备点「取消激活」时，
`POST /api/deactivate` 会真正释放服务端名额。许可证里也签入了设备 ID，
续签和停用不能拿另一台设备的 ID 冒充。

拦得住：一个码卖给一百个人。
拦不住：五个人合买一个码。这个损失可以接受。

### 第三层 · 定期回连（防长期复制品，且不伤离线用户）

许可证里的**签发时间是签过名的，改不了**。客户端据此知道自己多久没和服务器对过话：

| 距签发 | 行为 |
| --- | --- |
| < 14 天 | 什么都不做 |
| 14 天后 | 有网就悄悄换一份新的（`POST /api/refresh`），用户毫无感觉 |
| 45 天后 | 一直换不到新的才暂停 Pro 功能，提示「联网校验一次」 |

关键在于**失败一律静默**：没网是常态，不弹任何东西。
只有服务端明确回答 `revoked`（退款、滥用）或 `device_deactivated`
（本机名额已被释放）才会就地清除授权 ——
**网络错误绝不导致降级**。

45 天的宽限足够覆盖任何正常的断网场景。真正被卡住的，
是那些拿着一份复制品长期离线使用的。

拦得住：复制的许可证在 45 天后失效；退款用户在下次回连时失效。
拦不住：改系统时间往回调。判断用的是本机时钟 —— 这是离线校验的固有代价，
要堵死就得强制联网，那会把所有没外网的正当用户一起挡住。

### 第四层 · 加固（提高逆向门槛）

- macOS / 桌面端：`-ldflags="-s -w"` 去掉符号表
- Android：R8 混淆（`proguard-rules.pro` 已配）
- 公钥硬编码在客户端里，能被 patch，但要动二进制

这一层只是抬高门槛，不指望它拦住谁。

## 三端的差别

| | macOS | Android | iOS |
| --- | --- | --- | --- |
| 收款 | Waffo | Waffo（不上架 Google Play） | **App Store 内购** |
| 授权 | 激活码 | 激活码 | StoreKit 收据 + 通用许可证 |
| 离线 | 完全离线 | 完全离线 | StoreKit 本地收据 |

iOS 必须走内购：只要 App 里能用上在网站买的东西，Apple 就要求同一功能也提供 IAP
（`3.1.3(b)` 多平台服务）。美国区可以在 App 内放外链引导，其他区不行。

## 运维

```bash
npm run keygen    # 生成签名密钥，只跑一次，私钥直接写进 .env 不打印
npm run setup     # 在 Waffo 上创建三个档位的商品
npm run selftest  # 授权逻辑自检
npm run e2e       # 端到端演练（需要服务在跑）
npm start         # 启动服务
```

### 密钥

`.env` 里有两把私钥，都不进版本库：

- `WAFFO_PRIVATE_KEY` —— 泄漏了可以在 Waffo 后台轮换
- `LICENSE_PRIVATE_KEY` —— **泄漏了没法轻易换**：换掉会让所有已售出的许可证一起失效。
  它比 Waffo 那把还敏感。要换的话得保留旧公钥做过渡期。

公钥嵌在 `desktop/internal/license/key.go`，泄漏无所谓，它只能验证不能签发。

### 改了签发或校验逻辑之后

务必跑一遍跨语言对拍：

```bash
cd licensing && npm run selftest
node --experimental-strip-types src/mktoken.ts lifetime > ../desktop/internal/license/testdata/lifetime.token
cd ../desktop && go test ./internal/license/
```

签名覆盖的是 base64 那串字符本身，不是解码后的 JSON。
两端只要有一端理解错，客户端就永远验不过线上签发的许可证 ——
而这种错只有等第一个用户投诉才会暴露。

## 本机装一份开发许可证

验证 Pro 功能的完整路径（付费墙、导出、恢复购买…）不用真买一个码：

```bash
cd licensing
node --experimental-strip-types src/devlicense.ts lifetime   # 或 year / years3
```

它会向桌面端要许可证路径和 device id（`go run ./cmd/licpath`），签一份绑到
这台机器的许可证并直接装好。撤销就是删掉那个文件再重启桌面端。

路径和 device id 都问桌面端自己要，不在这边另写一份 —— 分叉的结果是
「装了却不生效」，查起来很费时间。

和 `mktoken.ts` 别搞混：那个是给 Go 端做跨语言对拍的裸串，不绑设备、不落盘。
