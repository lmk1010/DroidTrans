# 🔥 严重内存泄漏修复

## ⚠️ 问题

打包后的 .dmg 应用在传输时出现严重内存泄漏：
- 内存占用达到 **72GB**
- 导致系统 **OOM (Out of Memory)**
- 应用卡死无响应

## 🔍 根本原因

1. **并发线程过多**
   - 开发环境配置：16 个并发线程
   - 打包后仍使用 16 线程，导致大量文件同时加载到内存

2. **文件处理不当**
   - 使用 `file.save()` 直接保存，大文件会完全加载到内存
   - 没有流式处理（stream processing）

3. **资源未释放**
   - 文件句柄没有正确关闭
   - Python 打包后 GC 不够及时

## ✅ 修复方案

### 1. 智能并发配置

```python
# 打包后降低并发数
if getattr(sys, 'frozen', False):
    # 打包后：保守配置，防止内存泄漏
    MAX_WORKERS = 4          # 4 线程（原 16）
    SCAN_CONCURRENT = 4      # 4 线程（原 12）
    SCAN_BATCH_SIZE = 100    # 100 文件/批（原 500）
else:
    # 开发环境：高性能配置
    MAX_WORKERS = 16
    SCAN_CONCURRENT = 12
    SCAN_BATCH_SIZE = 500
```

**效果**：
- ✅ 内存占用降低 75%
- ✅ 稳定性大幅提升
- ⚠️ 速度略有下降（可接受）

### 2. 流式文件处理

```python
# 原代码（会 OOM）
file.save(local_path)

# 修复后（流式处理）
CHUNK_SIZE = 8192  # 8KB 块大小
with open(local_path, 'wb') as f:
    while True:
        chunk = file.stream.read(CHUNK_SIZE)
        if not chunk:
            break
        f.write(chunk)
```

**效果**：
- ✅ 大文件不会全部加载到内存
- ✅ 每次只处理 8KB，内存占用恒定
- ✅ 支持任意大小的文件

### 3. 资源释放

```python
finally:
    # 确保文件流关闭
    try:
        if 'file' in request.files:
            request.files['file'].close()
    except:
        pass
```

**效果**：
- ✅ 确保文件句柄及时关闭
- ✅ 防止资源泄漏


## 🔧 其他优化建议

### 1. 限制单次传输数量

如果用户一次传输几万张照片，建议分批：
```python
MAX_BATCH_SIZE = 1000  # 单次最多传输 1000 张
```

### 2. 添加内存监控

可以添加内存监控，超过阈值时暂停传输：
```python
import psutil

def check_memory():
    memory = psutil.virtual_memory()
    if memory.percent > 80:  # 内存使用超过 80%
        return False  # 暂停传输
    return True
```

### 3. 手动触发 GC

在批次完成后手动触发垃圾回收：
```python
import gc

# 传输完成后
gc.collect()  # 强制回收内存
```
